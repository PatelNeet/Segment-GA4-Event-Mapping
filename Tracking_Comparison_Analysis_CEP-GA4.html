4 — Cross-doc naming & mapping notes

Fly-Out / Pop-Up naming style: the Pop-up / Fly-out framework events are written as “Fly-Out … / Pop-Up …”. Keep the wording identical across both docs so automated string-matching doesn’t break.
file_download name variant: CEP writes the GA4 target as “file_download (automatic collected events when enabled)” — the parenthetical should be dropped so it matches the plain file_download event name used elsewhere.

5 — Other observations

Overloaded GA4 events: pdp_interaction (×5), pcc_customize_later_interaction (×4), nav_click (×3), cart_interaction (×2), plp_interaction (×2) each fire from multiple GTM tags. pdp_interaction in particular collapses tier-select, attribute-select, product-text and review-CTA clicks into one event — ensure gtm_event_sub_name is always populated so it can be segmented in GA4 / BigQuery.
The ecommerce core (Product Funnel) is the most complete area — 12/13 events mapped. view_item_list → view_item → select_item → add_to_cart → begin_checkout → add_shipping_info / add_payment_info → purchase all appear in both docs; the only intentional gap is “Checkout Step Viewed” (no GA4 event).
CEP-first rollout pattern: the newest frameworks (Chat, Survey, Ratings & Reviews, Experimentation) are CEP-defined but minimally wired to GA4 — consistent with defining the taxonomy before completing GA4 implementation. Track as a migration backlog.
Consent / privacy gap: consent-related GA4 tags (user_consent, do_not_track, dns_form_interaction) fire with no CEP framework covering them — worth flagging to compliance given onetrust_consent is a global param on every event.
